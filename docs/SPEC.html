1. 목적·범위

목적연구전담부서 연구원(이현우)이 매일 연구개발 활동을 정부 기준에 맞는 전자연구노트로 기록·결재·보존하여, 정부지원금(국가R&D 과제, 연구인력개발비 세액공제, 창업보육·바우처 등) 수행·정산·실태점검 시 연구활동 증빙으로 제출할 수 있게 한다.
시스템명AMP RNote (전자연구노트) — 사내 서버 설치형 웹앱
1차 범위일일 연구노트 작성 · 수정이력 · 해시체인 · 결재(기록→검토→확인) · 자동메일/카톡 알림 · GitHub 푸시 자동수집 · 관련 파일경로 기록 · Claude 평가/다음할일 · 피드백 · 주간계획 · 일일진도 · PDF(표지·목차·속지) · 열람대장 · 백업
범위 외(2차)공인 전자서명인증사업자 인증서 연동(9.3), RFC 3161 외부 시점확인(TSA) 상용 연동, 다과제·다연구원 확장 UI
사용자 규모초기 3명(기록자 1, 검토자 1, 확인자 1) — 연구원 추가 가능 구조로 설계

2.2 요건 → 구현 매핑

#정부·실무 요건등급구현 방법검증(19장)
R1기록자의 전자서명인증 기능필수사용자별 Ed25519 서명키 + 서명 PIN + TOTP 2단계 로그인. 제출 시 노트 해시에 전자서명. 2차: 공인 인증서 연동(9.3)T-03
R2연구기록 입력일·시간 자동기록필수모든 시각은 DB 서버시각(now())만 사용, 클라이언트 시각 입력 불가. 작성일자 = 서버 기준 KST 날짜. 서버 NTP 동기화T-01
R3기록의 위·변조 확인 기능필수SHA-256 해시체인 + 일일 머클루트 앵커링(별도 Git 저장소 커밋 + 대표 메일 발송). 검증 화면 제공T-04, T-05
R4수정 시 영구적으로 남는 수정표시필수UPDATE/DELETE 금지(append-only). 수정은 새 Revision + 수정사유 필수. 화면·PDF에 취소선/수정표시T-02
R5기록자·확인자 서명 및 날짜필수결재선: 기록자(이현우) → 검토(신재민) → 확인자(신흥섭). 각 단계 서명·일시 저장. 속지 하단 서명란 출력T-06
R6연구개발기관명·일련번호·과제명·쪽번호필수권(Notebook) 일련번호 AMP-RN-YYYY-NNN, 쪽번호 연속 자동부여(누락·중복 불가, DB unique), 과제명·계정번호 표지 출력T-07
R7기본 기재사항 (과제명, 작성일자, 실험명, 목적, 방법, 결과, 서명/일자)필수필수 필드 미입력 시 제출 불가T-08
R8추가 기재사항 (참고문헌, 측정·획득조건, 특이/예상외 결과, 표준절차 참조·수정, 새 가설, 요인 관계, 해석·평가·결론, 실패 데이터)권장선택 필드로 제공, 해당 시 입력. "실패 데이터도 반드시 기재" 안내 문구 상시 표시—
R9사실이 아닌 의견은 기록하지 말 것 / 연구노트는 업무수첩이 아님필수Claude 평가·피드백은 노트 본문과 분리 저장·표시("AI 평가(참고) — 연구노트 본문 아님"). AI 초안은 기록자가 섹션별 "사실 확인" 체크 후에만 본문 반영T-09
R10직접 기입 불가 자료(사진·데이터·출력물) 첨부필수첨부파일 SHA-256 기록, 노트 해시에 포함. 관련 파일경로(md 등) 필수 기록T-10
R11목차(중요 페이지·내용 요약)권장"중요" 표시 노트 → 권별 목차 자동 생성(PAGE / DESCRIPTION)T-11
R12표지 (일련번호, 과제명·계정번호, 권번호, 기록자, 작성기간, 소속·사번·전화, 보관장소·책임자)필수Notebook 메타데이터 → PDF 표지T-11
R13열람 통제·외부 비공개·열람대장필수역할 기반 권한, 모든 조회를 AuditLog(VIEW)로 기록 → 열람대장 화면T-12
R14보존(사용 후 연구노트 이관·장기보존)·폐기 절차필수과제 종료 시 권 마감(CLOSED) → 읽기전용. 보존기간 기본 30년(설정값), 폐기는 대표 승인 + 폐기대장. 일일 암호화 백업T-13

7.3 노트 안의 파일경로 기록 규칙

  • 모든 노트는 fileRefs 1건 이상 필수 — 제출 시 검증.
  • 형식: <저장소명>:<상대경로> + 변경유형(A추가/M수정/D삭제/R참조) + 커밋 SHA(앞 7자리). 예: ampfmea:docs/import/FC_SHEET_RULE.md (M, a1b2c3d)
  • md 문서는 별도 강조 표시(isDoc=true): *.md, *.mdx, CLAUDE.md, SKILL.md, docs/** — 목차·주간보고에 "작성/수정 문서" 목록으로 집계.
  • 저장소 밖 자료(엑셀 테스트데이터 등)는 첨부 업로드 후 서버 경로 자동 기록.

9. 무결성·전자서명

9.1 해시체인

contentHash = SHA256( canonicalJSON({ body, fileRefs(sorted), attachments.sha256(sorted), noteDate, pageNo, notebookSerial }) )
chainHash   = SHA256( prevChainHash + "|" + contentHash + "|" + createdAt(ISO, 서버) + "|" + revNo )
// prevChainHash = 시스템 전체 직전 Revision의 chainHash (최초: "GENESIS-AMP-RNOTE")
// 체인 직렬화를 위해 Revision 생성은 pg_advisory_xact_lock(42) 안에서 수행

9.2 일일 앵커링 (매일 23:59, worker)

  1. 당일 생성된 모든 chainHash로 머클루트 계산 → HashAnchor 저장
  2. 확정 노트 Markdown + 앵커 JSON을 /srv/amp-rnote/ledger Git 저장소에 커밋 → 원격(비공개 GitHub amp-rnote-ledger)에 push — GitHub 서버 시각이 제3자 기록 역할
  3. 신흥섭 대표 메일로 "YYYY-MM-DD 연구노트 해시원장: merkleRoot, 건수" 발송 (외부 메일함 = 독립 보관 증빙)

9.3 전자서명

단계방식상태
1차 (본 개발)최초 로그인 시 사용자별 Ed25519 키쌍 생성, 6자리 서명PIN으로 개인키 암호화. 제출·검토·확인 시 [TOTP 로그인 세션 + 서명PIN] 입력 → chainHash 서명 저장. 검증 화면에서 공개키로 검증구현
2차「전자서명법」상 전자서명인증사업자 인증서(공동인증서·민간 간편인증 등) 연동으로 기록자 본인확인 강화대표 확인 전담기관 점검 시 1차 방식 인정 여부 확인 후 결정

lib/sign.ts는 Signer 인터페이스로 추상화해 2차 연동 시 교체만 하도록 한다.

10. GitHub 푸시 연동

10.1 Webhook (자동수집의 원천)

  • 대상 저장소: 과제에 등록된 저장소(예: Smart FMEA 저장소) → Settings › Webhooks › https://rnote.ampbiz.co.kr/api/webhooks/github, 이벤트 push, Secret = GITHUB_WEBHOOK_SECRET
  • 수신 시 X-Hub-Signature-256 HMAC 검증 → 커밋별 GitHub API(GET /repos/{o}/{r}/commits/{sha})로 변경파일 조회 → GitCommit 저장
  • 작성자 githubLogin → User 매핑, 서버 KST 날짜의 해당 기록자 노트(없으면 DRAFT 생성)에 자동 연결, FileRef(source=GIT) 생성, md 파일은 isDoc=true
  • 확정(CONFIRMED)된 날짜의 노트에는 연결하지 않고 다음 영업일 DRAFT로 연결

10.2 푸시 후 스크립트 — scripts/rn-push.sh

Git에는 post-push 훅이 없으므로, 개발자는 git push 대신 rn-push를 사용한다 (alias 등록). 푸시 후 오늘 작업 메모와 로컬 테스트 결과를 노트 초안에 보내고 초안 URL을 띄운다.

#!/usr/bin/env bash
# scripts/rn-push.sh — git push 후 연구노트 초안에 작업 정보 전송
# 설치: git config --global alias.rnp '!bash ~/amp-rnote/scripts/rn-push.sh'
# 사용: git rnp            (또는 git rnp origin main)
set -euo pipefail
RNOTE_URL="${RNOTE_URL:-https://rnote.ampbiz.co.kr}"
RNOTE_TOKEN="${RNOTE_TOKEN:?RNOTE_TOKEN 환경변수 필요 (앱 > 설정 > 개인 토큰)}"

REPO=$(basename -s .git "$(git config --get remote.origin.url)")
BRANCH=$(git rev-parse --abbrev-ref HEAD)
UPSTREAM=$(git rev-parse --abbrev-ref --symbolic-full-name @{u} 2>/dev/null || echo "")
RANGE=${UPSTREAM:+$UPSTREAM..HEAD}
COMMITS=$(git log ${RANGE:--n20} --pretty=format:'%H' | paste -sd, -)

git push "$@"                                   # 1) 실제 푸시

[ -z "$COMMITS" ] && { echo "푸시할 새 커밋 없음"; exit 0; }
FILES=$(git diff --name-status ${UPSTREAM:-HEAD~1} HEAD 2>/dev/null || true)

echo "오늘 작업 메모(사실만, 한 줄, 엔터=생략):"; read -r MEMO || MEMO=""
TEST_SUMMARY=""
if [ -f package.json ] && grep -q '"test"' package.json; then
  read -r -p "테스트 실행 결과 첨부? [y/N] " RUN
  [ "${RUN:-N}" = "y" ] && TEST_SUMMARY=$(npm test --silent 2>&1 | tail -n 15 || true)
fi

PAYLOAD=$(jq -n --arg repo "$REPO" --arg branch "$BRANCH" --arg commits "$COMMITS" \
  --arg files "$FILES" --arg memo "$MEMO" --arg test "$TEST_SUMMARY" \
  '{repo:$repo,branch:$branch,commits:($commits|split(",")),nameStatus:$files,memo:$memo,testSummary:$test}')

RESP=$(curl -fsS -X POST "$RNOTE_URL/api/git/push-report" \
  -H "Authorization: Bearer $RNOTE_TOKEN" -H "Content-Type: application/json" -d "$PAYLOAD")
echo "연구노트 초안: $(echo "$RESP" | jq -r .draftUrl)"
echo "※ 18:00 전 초안을 확인·보완 후 제출하세요."

Windows용 scripts/rn-push.ps1도 동일 동작으로 작성. 서버는 webhook과 push-report를 커밋 SHA로 중복 제거한다.

# AMP RNote — Claude Code 작업 규칙
## 프로젝트
- 정부기준 전자연구노트 시스템. 명세: docs/SPEC.html (최우선)
- 스택: Next.js 14 App Router, TypeScript strict, Prisma, PostgreSQL 16

## 절대 규칙 (위반 시 작업 중단 후 보고)
1. NoteRevision / AuditLog / HashAnchor 에 update/delete 코드 금지 (append-only)
2. 모든 시각은 서버 DB now() — 클라이언트 시각을 저장하지 말 것
3. 해시 계산은 src/lib/hash.ts canonicalJSON만 사용, 필드 추가 시 hashVersion 올리고 DECISIONS.md 기록
4. AI 생성 텍스트는 본문과 분리(AiEvaluation) — 본문 반영은 기록자 사실확인 체크 후만
5. 노트 제출은 필수필드 + fileRefs ≥ 1 검증 통과 시에만
6. 모르는 설정값은 TODO_CONFIRM, 지어내지 말 것
7. 외부 발송(메일·카톡)은 NOTIFY_DRY_RUN=true 기본, 테스트에서 실발송 금지

## 작업 방식
- docs/SPEC.html 18장 Day 단위로 진행, 끝나면 19장 해당 T-xx 시험 작성·통과
- 매 Day 종료: docs/PROGRESS.md 갱신 → 커밋 메시지 "D{n}: 요약"
- 커밋 후 `git rnp`(scripts/rn-push.sh)로 푸시 — 이 저장소도 연구노트 대상
- 변경한 md 문서 경로는 커밋 메시지 본문에 나열

## 명령
- npm run dev / npm run test / npm run verify:chain / npm run worker
- docker compose up -d db
